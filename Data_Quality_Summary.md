## Checks, findings and decisions

| Check | Table | Finding | What it means | Action taken |
|---|---|---|---|---|
| Dictionary vs files | all | 2 field mismatches (e.g. fipscountycode, middle) | The dictionary describes fields that the supplied file does not contain | Fields used in this analysis all exist in encounters.csv; the mismatches do not affect the analysis |
| Key integrity | encounters, procedures | All foreign keys match their parent tables (100%) | Tables can be joined safely | No records dropped by joins |
| Single organisation | organizations | Only 1 organisation (MASSACHUSETTS GENERAL HOSPITAL) | Findings cannot be generalised beyond this one hospital | Stated as a limitation |
| Duplicates | encounters | 0 fully duplicated rows, 0 repeated encounter Ids | No duplicate records | Nothing removed |
| Same patient/time/class | encounters | 27 encounters share patient, start time and class with another | Possibly separate services at one visit rather than errors | Kept (not deleted); noted as a limitation |
| Missing values | encounters | REASONCODE/REASONDESCRIPTION blank in 70% of encounters; no other gaps | Blank means no reason recorded, not a data error | Left blank; columns not used |
| Missing values | procedures | REASONCODE/REASONDESCRIPTION blank in 77% of procedures | Same meaning as above | Left blank; columns not used |
| Data types | encounters | START and STOP stored as text | Needed as dates to calculate duration | Converted to datetime (UTC) in Section 2.5 |
| Privacy | patients | patients.csv holds names and addresses | Personal details must not appear in outputs or a public repository | Only the Id column is loaded; patients.csv is excluded from Git |
| Cost reconciliation | encounters, procedures | Total claim = base + procedure costs for only 30% of encounters; procedure costs sum to 104% of total claims | Cost fields are not simple components of each other (other items such as medications are not in the pack) | Total claim cost is analysed as recorded; it is not broken down into parts |
| Dates | encounters | All dates parse; 0 negative durations; 4 encounters last > 1 year; first/last years are partial | Extreme durations are unusual but not impossible for long-running care episodes | Kept and flagged; sensitivity checks in Section 6 |
| Duration structure | encounters | Duration is a single fixed value for some classes; every inpatient stay is >= 24 h | Duration has limited independent information; '>24 hours' vs '>= 24 hours' differ | Both definitions reported; H2 also tested within each class |
| Zero claim cost | encounters | 89 encounters have total claim cost = 0 although base cost is positive | Claim total is lower than its own base cost, which is inconsistent | Kept; excluded only from log-scale charts; flagged |
| Payer coverage | encounters | 49% of encounters show zero coverage, including 4,779 with a named insurer | Zero coverage is ambiguous (not-recorded vs not-covered) | Reported as 'recorded coverage'; never read as uninsured |
| Repeated records | encounters | 974 patients; median 14 encounters each; maximum 1,381 | Encounters from the same patient are not independent | Robustness test using one encounter per patient (Section 6) |

**Principle applied:** no row was deleted and no missing value was filled. Rows with unusual values are flagged and tested for their influence instead.
